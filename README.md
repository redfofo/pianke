# 片刻 Web 播放器

连接用户自行配置的 Happy Capy 服务的独立 Web 播放器，不内置上游地址。前端使用 React 19、TypeScript、Vite、shadcn/ui（radix-nova）与 Tailwind CSS v4、Zustand、TanStack Query、React Router、Motion、dnd-kit、react-resizable-panels、ArtPlayer、hls.js（light 构建）；服务端使用 Fastify。各库的分工见下方“前端约定”。不会修改 Happy Capy 服务或它托管的 JS。

## 功能

- 从 Happy Capy `/api/v1/components` 读取已安装且 `enabled: true` 的来源；上游新安装的组件自动出现，无需更新本项目。红果、黄豆、野果、剧果、帝果、51吃瓜走专用后端接口适配，其余来源（含黄果、MissAV 及上游新增来源）在子进程中直接运行上游组件。
- 分类、组件特有筛选、搜索、分页、详情、分季与选集；所有内容来自实际上游，无演示数据。
- MP4、HLS、进度拖动、倍速、音量、全屏、上一集/下一集、自动连播；自动切换下一集时保持当前全屏状态。只有上游提供多线路或 HLS 多码率时，播放器设置菜单中才显示对应的“播放线路”“清晰度”选项。手机端支持手势拖动进度、长按倍速、锁定和全屏自动横屏。播放区按视频实际宽高比自适应，竖屏短剧不再被压在横向画框里；支持系统锁屏/通知栏的媒体控制（Media Session），可在锁屏上切换上一集/下一集。
- 管理员建号、账号密码登录，不开放注册。收藏和逐集观看进度按账号独立保存到服务器 SQLite；同一账号跨浏览器、跨设备续播。记录保留来源与详情链接，重新获取播放地址，不保存过期媒体链接作为入口。
- 管理员可为普通账号分配可浏览来源，支持单选、多选、全选或全部取消。来源列表、搜索、详情、播放、媒体转发和账号记录均由服务端校验权限，不仅隐藏前端入口。
- 桌面来源侧栏；手机端使用底部标签栏、横向来源标签和连续滚动加载（桌面保留分页）；键盘焦点、错误提示、骨架屏与空状态。
- 手机窄屏与触摸设备的输入框文字至少为 16px，避免 iOS 聚焦输入框时自动放大；保留双指缩放，不限制 viewport 最大缩放比例。
- 发现页顶部的“继续观看”栏；跨已开启来源搜索（同时最多请求 3 个来源，每个来源显示第一页）。
- “继续观看”卡片下可点击“移除记录”，删除当前账号该剧的观看记录及全部剧集进度，同时从“观看记录”页移除；收藏和其他账号不受影响。删除失败时保留卡片并显示错误，删除最后一条后隐藏“继续观看”栏。重新播放会产生新的观看记录。
- 列表与详情在浏览器内缓存 5 分钟，从播放页返回列表不重新请求上游，并恢复滚动位置。
- 浅色、深色与跟随系统三种外观；可作为 PWA 添加到主屏幕（只缓存应用外壳，不缓存接口和视频）。
- 来源状态页区分浏览、搜索、详情和实际播放。检查按钮只检查列表；播放状态必须来自浏览器的视频解码/播放事件。
- 管理员在“设置”中编辑上游地址，保存后立即应用并持久化到服务端；所有账号共享，普通用户不能读取或修改上游配置。
- “内容来源”提供独立显示开关，关闭后隐藏首页来源入口、该来源内容、“继续观看”条目和搜索结果；收藏与历史记录不删除。开关仅保存在当前浏览器，新出现的受支持来源默认开启；上游移除再恢复时保留本地选择。全部关闭时显示设置入口，不自动打开其他来源。
- 来源列表在首次加载、进入设置、页面重新可见或获得焦点时同步，页面可见期间每 30 秒更新，也可手动刷新。上游关闭或卸载的来源从设置和首页一同移除；列表读取失败保留上次成功结果并显示错误，不将故障当成空列表。已启用但组件下载失败的来源仍显示诊断错误。
- “播放偏好”提供“服务器代理中转”开关，默认开启；关闭后严格使用浏览器直链播放，不自动回退中转。偏好保存在当前浏览器，下次获取播放地址时生效。默认打开上次浏览的可用来源。
- 分类、搜索、详情、收藏、观看记录和系统媒体封面统一使用本站 `/api/posters/:id`；外网浏览器不需要访问 Happy Capy 的内网地址。后台目录同步会提取详情、分季/分集和海报，详情写入 SQLite，已验证的海报字节写入 `DATA_DIR/posters`，网页和 Emby 客户端优先读取本地缓存。
- 媒体库搜索（Emby 客户端搜索、站内来源搜索的本地兜底、`/api/catalog?q=`）使用 SQLite FTS5 trigram 全文索引：3 个及以上字符的关键词只读取命中行，百万级媒体库从约 0.5 秒降到 1 毫秒左右；1–2 个字符的关键词无法使用 trigram，仍逐行匹配。匹配规则不变（名称或简介包含关键词，不区分 ASCII 大小写）。升级后首次启动会在后台分批为已有条目建立索引（130 万条约数秒、索引约 80 MB），完成前搜索照常可用，只是沿用原有速度；索引由触发器随媒体库写入自动维护。

## Docker 部署

需要 Docker Engine 与 Compose，部署机器须能访问用户配置的 Happy Capy 服务和组件依赖的上游站点。

```sh
# 首次部署且尚无 .env 时，复制示例，填写 ADMIN_PASSWORD（10–128 个字符）。
# 已有 .env 则补充 ADMIN_PASSWORD，不要覆盖现有配置。
# cp .env.example .env
docker compose up -d --build
```

首次启动前必须设置 `ADMIN_PASSWORD`；不提供默认密码。启动后使用 `ADMIN_USERNAME`（默认 `admin`）登录，再打开“设置”填写可信 Happy Capy 的 HTTP(S) 根地址并保存。也可以使用 `CAPY_BACKEND_URL` 提供初始上游地址。

默认入口：`http://部署机器IP:8788`。健康检查：`GET /api/health`。

```sh
docker compose logs --follow player
docker compose down
```

容器以非 root 用户运行，根文件系统只读，移除 Linux capabilities，限制进程与内存。上游配置写入 `/app/data/config.json`，账号、会话、收藏、进度和详情索引写入 `/app/data/accounts.sqlite`，海报字节写入 `/app/data/posters`；Compose 使用 `player_data` 命名卷持久化。普通重启、重建和 `docker compose down` 不会删除该卷；`docker compose down -v` 会删除账号、记录和缓存。备份时先停止服务，再备份整个数据目录（含可能存在的 SQLite WAL 文件）；不要只复制运行中的主数据库文件。

### 环境变量

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `ADMIN_USERNAME` | `admin` | 仅首次初始化创建的管理员用户名，3–32 位字母、数字、下划线、点或短横线，不能以点或短横线开头 |
| `ADMIN_PASSWORD` | 无 | 首次启动必填，10–128 个字符；数据库已有管理员后不覆盖其密码 |
| `SESSION_COOKIE_SECURE` | `false` | HTTPS 反向代理部署时设为 `true`；本地 HTTP 开发保持 `false` |
| `CAPY_BACKEND_URL` | 空，可选 | 仅在没有已保存配置时使用的初始上游根地址 |
| `DATA_DIR` | `./data` | 账号数据库与上游配置目录，须可写；Compose 固定为 `/app/data` 并挂载命名卷 |
| `PLAYER_PORT` | `8788` | Compose 对外端口 |
| `PLAYER_BIND_ADDRESS` | 空（所有接口） | Compose 发布端口的绑定地址；同机反代可设 `127.0.0.1`，容器或远程反代需使用可达接口 |
| `PUBLIC_BASE_URL` | 空 | UDP 局域网发现返回给客户端的完整公网/局域网地址，例如 `http://192.168.1.20:8788`；Docker 部署建议填写 |
| `PORT` | `8788` | 非容器 Node 服务监听端口；容器内部固定 8788 |
| `EMBY_DISCOVERY_PORT` | `7359` | Compose 发布的 Emby 局域网 UDP 发现端口 |
| `TRANSCODE_MAX_SESSIONS` | `1` | 同时运行的 FFmpeg HLS 转码任务上限 |
| `TRANSCODE_VIDEO_CODEC` | `libx264` | 视频转码编码器；可选 `h264_qsv`、`h264_nvenc`、`h264_vaapi`，硬件模式还需映射对应设备 |
| `TRANSCODE_PRESET` | `veryfast` | `libx264` 编码预设 |
| `WIDGET_TIMEOUT_MS` | `120000` | 原生组件执行上限，取值限制为 1000–120000 毫秒 |
| `CATALOG_SYNC_INTERVAL_MINUTES` | `360` | 后台目录扫描间隔，最小 15 分钟 |
| `CATALOG_SYNC_MAX_PAGES` | `100` | 每个来源模块单次扫描的最大页数 |
| `CATALOG_DETAIL_CACHE_DAYS` | `7` | 已缓存详情再次从上游提取前的最长天数，最小 1 天 |
| `CATALOG_DETAIL_CONCURRENCY` | `3` | 后台并行提取详情和预缓存海报的数量，范围 1–8 |
| `POSTER_CACHE_MAX_MB` | `2048` | `DATA_DIR/posters` 持久海报缓存容量，最小 128 MiB |
| `POSTER_CACHE_MAX_AGE_DAYS` | `90` | 未更新持久海报的保留天数，最小 7 天 |
| `TRUSTED_FAKE_IP_CIDRS` | 空 | 可选，逗号分隔的 IPv4 CIDR。系统 DNS 为 fake-IP 时，信任这些网段的服务端上游连接，例如 `198.18.0.0/15` |
| `UPSTREAM_DOH_URL` | 空 | 可选 DNS JSON 接口，要求 HTTPS 公网 IP 地址，例如 `https://1.1.1.1/dns-query` |

普通网络无需设置 DoH。如果公网域名被解析到 `198.18.0.0/15` 的 fake-IP 网段，可配置 `UPSTREAM_DOH_URL` 获取真实公网地址；不会因此放开内网地址访问。启用该选项会将公网源域名的 DNS 查询发送给所配置的解析服务。Happy Capy 内网地址仍使用系统 DNS。DoH 不替代代理，不能解决源站的地区限制或连接封锁。也可以不用 DoH，改为设置 `TRUSTED_FAKE_IP_CIDRS=198.18.0.0/15`：服务端沿用系统 DNS，并允许连接该网段，由 fake-IP 网关按域名分流。此时服务端访问的真实目标由网关决定，只能信任自己控制的网关。该设置不接受与内网、环回、组播重叠的网段，Happy Capy 以外的内网地址仍被拒绝。两者同时设置时 DoH 优先。浏览器直链播放使用客户端自身的 DNS，不受这两个设置影响。DoH 返回的 CDN 节点取决于解析服务所在地区：国内视频源用 `https://1.1.1.1/dns-query` 可能被调度到海外节点，中转速度明显下降，可改用 `https://223.5.5.5/resolve` 等就近解析的 JSON 接口。

不要将 `CAPY_BACKEND_URL` 设为播放器自身地址，避免请求循环。如果与 Happy Capy 部署在同一台机器，请更改 `PLAYER_PORT`，保留其上游端口。

推荐在网页“设置”保存地址；保存结果会显示“已保存”。地址须为可信服务的 HTTP(S) 根地址，不含账号密码、子路径、查询参数或片段，不能指向播放器自身。地址前后的空白与根路径末尾的 `/` 会被规范化。

如需通过启动环境提供初始地址，可在 `.env` 中填写；以下占位域名须替换为实际服务：

```dotenv
CAPY_BACKEND_URL=https://capy.example.com
```

配置优先级：**`DATA_DIR/config.json` 中已保存的地址 > 进程环境变量 > `.env`**。`.env` 由 `npm start`、开发服务或 Compose 读取；已保存配置存在时，修改启动环境不会覆盖网页保存的地址。未配置上游时仍可启动并访问登录页；管理员登录后在“设置”填写地址，来源接口会在上游未配置时返回设置指引。上游不可达时，来源接口报告请求错误；`/api/health` 只表示播放器服务存活，不保证上游可用。

网页保存后立即生效，无需重启或重新构建。服务端先原子写入配置文件，成功后再应用；写入失败会报错并保留当前地址。保存不会预先探测上游可用性，保存成功与来源可用是两回事。若仍有来源请求在执行，保存会返回“内容源正在使用”，等待操作结束后再试；关闭浏览器请求不一定意味着服务端操作已经结束。

切换会清空旧来源缓存、状态、媒体凭证与海报内存缓存，旧播放和封面链接失效，已开始传输的普通媒体流可能继续完成。收藏、观看记录和偏好不会删除，也不会自动迁移到新上游；需要重新打开剧集获取新播放地址。`.env` 和本地 `data` 目录已被 Git 忽略，不要提交本机配置。

**上游配置为服务端共享，仅管理员可读取和修改。** 所有来源、解析、媒体与账号记录接口都要求登录；普通账号不能创建用户或访问管理员接口。跨站写入被拒绝，上游组件仍只应来自可信服务。公网部署必须使用 HTTPS、强密码和反向代理访问限制。

### 账号与独立记录

1. 首次启动通过环境变量创建管理员。之后改变 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 不会重置数据库中的账号。
2. 管理员登录后，进入“设置 → 管理账号”（`/admin/users`），填写用户名、初始密码并勾选“可浏览来源”创建普通账号。已有账号点击“编辑来源 → 保存权限”修改。用户名不区分大小写，不能重复；不会返回或保存明文密码。
3. 用户仅能读取、续播、删除和清空自己有权访问来源的观看记录与收藏。撤销权限只隐藏记录，不删除；清空也保留无权访问来源的隐藏记录，重新授权后恢复显示。逐集进度与每部剧最后观看的集数均独立；管理员也只在个人片库看到自己的记录。
4. 播放偏好、主题和来源显示开关仍属于当前浏览器。旧版本匿名 IndexedDB 记录没有账号归属，不自动导入，也不删除原浏览器数据库；上游共享的历史模块不再展示或允许查询。
5. 退出登录会撤销当前会话；切换账号整页重载，并通知同站点其他标签页清理旧界面。片库请求必须附带当前账号 ID，旧标签页即使使用了新账号 Cookie 也会被拒绝，不会把旧进度写入新账号。
6. 升级时已有账号保留原有来源权限；新建账号界面默认全选，可单选、多选或全部取消。全选保存当时已知来源的明确列表，上游之后新增的来源不会自动授权给普通账号，需管理员在账号管理中勾选。管理员始终拥有全部来源权限（含新增来源），不提供管理员来源编辑。
7. 权限保存在 SQLite，已有会话的后续请求立即采用新权限，无需重新登录。页面可见时每 30 秒及重新获得焦点时同步账号权限，权限变化会整页重载，清理旧列表、详情缓存和播放界面。媒体凭证绑定账号及来源，包括 HLS 子列表、分片、密钥和字幕；已开始传输的媒体响应不会强行中断，已交给客户端的外部源站直链无法由本站撤回。

密码使用随机盐与 scrypt 哈希；会话使用随机令牌、数据库内只保存令牌哈希，Cookie 设置 `HttpOnly`、`SameSite=Lax`，有效期 30 天，服务重启后可继续使用。登录有单 IP 失败次数与并发限制；反向代理部署下同一代理后的用户共享该限制，建议同时在代理配置登录限流。HTTPS 代理终止 TLS 时设置 `SESSION_COOKIE_SECURE=true`，应用不信任任意转发头。

### 单域名 HTTPS 反向代理

只公开本项目的独立域名根路径，无须把 Happy Capy 的端口或域名公开到外网。本项目服务器仍须能连接已配置的 Happy Capy 和公网内容源；这不是脱离上游独立采集。不要部署在 `/player/` 等子路径下。

1. 在已有 `.env` 中设置 `SESSION_COOKIE_SECURE=true`。如果 Nginx 与播放器部署在同一宿主机，还可设置 `PLAYER_BIND_ADDRESS=127.0.0.1`，避免播放器端口直接暴露；保留原来的管理员密码、上游配置和数据卷。通过 `docker compose up -d --build` 应用配置。
2. 在已有证书的 Nginx HTTPS `server {}` 内引入 [`deploy/nginx-location.conf`](deploy/nginx-location.conf)，替换原有的根 `location /`，不要重复定义。文件默认转发到 `http://127.0.0.1:8788`；修改了 `PLAYER_PORT` 时同步调整 `proxy_pass`。Nginx 在容器内时，`127.0.0.1` 指向 Nginx 自己，必须改用双方共享网络上的播放器服务地址，并采用该网络可达的部署方式。
3. 保持“服务器代理中转”开启，浏览器的视频、HLS 子列表/分片/密钥和海报都请求当前域名。关闭后仍是严格源站直链：客户端必须能访问源站，并满足跨域、防盗链和 HTTPS 限制，不自动回退代理。

提供的 Nginx 配置保留原始 `Host`、`Origin`、Cookie 和 Range 请求，关闭代理缓存和响应缓冲，并将读取/发送超时设为 300 秒。**不要把 `Host` 改成内网地址**，否则本站的跨站写入检查会拒绝登录、收藏和进度保存。不要对 `/api` 配置公共缓存；即使图片命中服务器内存缓存，仍需校验当前会话和来源权限。应用不信任任意 `X-Forwarded-*`，反代后的登录限流行为见上文。

验收时从不能访问内网上游的客户端登录，检查分类、搜索、收藏、观看记录、播放和拖动续播。开启中转时，网络面板中的图片/媒体请求应只访问播放器域名；响应中的详情链接可能包含上游地址作为内容标识，但浏览器不直接请求它。服务器须承担图片及视频中转流量，源站故障、地区封锁和浏览器解码限制仍然存在。


## 本地开发与构建

Node.js 24 或更高版本。`npm start` 和开发服务自动读取存在的 `.env`。

首次启动需在 `.env` 或进程环境中设置 `ADMIN_PASSWORD`；上游地址可以留空，由管理员登录后在“设置”中配置。服务会创建 `DATA_DIR` 与账号数据库。

```sh
npm ci
npm run dev
```

开发页面 `http://localhost:5173`，API 默认 `http://localhost:8788`。Vite 将 `/api` 转发至该端口；如果修改 Node 的 `PORT`，同时修改 `vite.config.ts` 的开发代理。

```sh
npm run build
npm start
npm test            # 服务端 node:test + 前端 Vitest
npm run test:e2e    # Playwright 冒烟测试（首次需 npx playwright install chromium；5174 端口被占用时设 E2E_PORT）
npm run lint        # ESLint
npm run format      # Prettier
npm run analyze     # 生成 dist/stats.html 包体积分析
npm audit
```

`npm run build` 包含 TypeScript 检查（`tsconfig.app.json` 前端、`tsconfig.node.json` 服务端与构建配置、`e2e/tsconfig.json` 端到端测试，分开检查，前端代码无法使用 Node 全局对象）、前端构建、服务端构建和组件子进程打包。端到端测试在 Vite 开发服务器上运行，所有 `/api` 请求都在浏览器内 mock，不需要上游或 Node 服务。生产页面位于 `dist/client`，服务端位于 `dist/server`，静态服务不暴露服务端文件。开发启动也会先构建组件子进程。

来源顺序和显隐只保存在当前浏览器，影响侧栏、来源标签、媒体库和全部来源搜索的排列，不改变账号权限。

## 接入方式

上游须提供 `/api/v1/components`，返回 `{ components: [{ id, title?, enabled, ... }] }`；来源列表采用已启用的组件。关闭来源以该接口状态为准，不依赖首页是否残留组件链接。

**上游新增来源无需更新本项目。** 每次读取组件列表时，`id` 符合 `^[a-z0-9][a-z0-9_-]{0,31}$` 的新组件会登记到 `DATA_DIR/sources.json` 来源注册表，随即可浏览、搜索、播放、同步媒体库，并出现在账号管理的来源勾选列表中。注册表只增不减：上游卸载或停用的来源仅从列表隐藏，账号授权、观看记录和媒体库条目保留，重新安装后恢复。内置来源保留本项目的中文名称，新增来源使用上游 `title`。

红果、黄豆、野果、剧果、帝果、51吃瓜六个后端型组件复用现有 `/api/v1/providers/...` 接口。其余来源（黄果、MissAV 及所有上游新增来源）通过独立 Node 子进程直接运行上游组件，兼容 `Widget.http`、`Widget.html`、`fetch` 等宿主能力；MissAV 明确使用标准 HLS 模式，而非桌面 mpv EDL。模块与筛选元数据使用 Acorn 静态解析，不在主服务中执行远程 JS。组件子进程最多同时运行 4 个，超出时排队等待（最长等于 `WIDGET_TIMEOUT_MS`），后台媒体库同步与用户请求共用该额度。组件访问 Backend 时只能使用自身的 `/api/v1/<id>/`、`/api/v1/providers/<id>/` 命名空间，越界请求单独失败、不中断组件。新增来源的详情地址对本项目不透明，只会交给该来源的组件处理；指向 Backend 时同样限于其自身命名空间。

子进程有超时、内存、网络请求数量和响应大小限制；Node 权限模型只允许读取已打包的 worker 文件，不允许写文件、启动其他进程或加载原生插件。**Node `vm` 仅用于变量命名空间，不是恶意脚本安全沙箱。Node 24 权限模型也不是完整网络沙箱；必须信任所配置 Backend 的组件发布者。** 不支持上传或执行任意 JS。

媒体地址只能由服务端的详情解析生成，客户端不能提交任意 URL 创建代理。需要转发的媒体使用随机短期凭证，URL 中不暴露 Cookie。请求校验并固定 DNS 解析结果，拒绝私网、环回与链路本地目标；仅允许配置好的 Backend 上已知媒体接口。重定向重新校验，跨域移除 Cookie/Authorization。

海报只接受服务器来源解析产生的候选地址，浏览器不能通过 URL 参数或收藏/进度正文创建任意图片代理。内网例外仅限当前 Backend 的图片代理接口（`/api/v1/providers/<id>/cover`、`/api/v1/<id>/cover`、`/api/v1/missav/cover`、`/api/v1/image-proxy`）；图片请求及重定向均校验目标，嵌套封面目标拒绝私网，不转发浏览器 Cookie/Authorization。响应按实际字节验证 JPEG、PNG、GIF、静态 WebP，拒绝 HTML、SVG、错误状态及不支持的格式，再尝试可信备用图或刷新上游候选；没有可用图片时返回明确错误，不伪装成成功占位图。

封面单图上限 8 MiB；服务器内存缓存最多 32 MiB/256 项、有效期 10 分钟，请求并发上限 8；验证通过的图片同时原子写入持久缓存，重启后无需再次请求上游。持久缓存默认最多 2 GiB、保留 90 天，按最久未更新项清理。浏览器收到 `private, no-store`，每次读取仍校验当前会话和来源权限；撤销来源权限或退出登录后不能继续从服务端读取缓存图片。旧收藏/观看记录在读取时转换为同源封面；空封面按原来源和内容标识懒加载恢复，不按相似标题误配，也不改动用户播放进度。源已下架且尚未缓存，或上游找不到精确条目时仍可能无封面。

开启“服务器代理中转”时，所有播放线路通过本站短期媒体凭证转发。HLS 转发覆盖子播放列表、相对分片地址、初始化片段与密钥 URI；MP4 保留 Range/Content-Range。播放凭证有效期六小时，服务重启后失效；重新选择剧集会解析新地址。

关闭开关时，本站仍负责浏览、详情和播放地址解析，但不探测、下载或改写视频媒体；将上游提供的 HTTP(S) 源站地址交给浏览器。对于已知 `/api/v1/stream/:token`、`/api/v1/playback/:token` 及其 `/media`、`/playlist.m3u8` 包装地址，只尝试上游的 JSON 播放解析接口；结果仍属于上游服务或上游拒绝直连解析时，提示失败，不把上游中转当作直链，也不自动恢复本站中转。仅有中转接口而未公开原始 URL 的来源，需要上游增加直链能力或手动开启中转。

直链播放不附加上游指定的 Cookie、Authorization、Referer、User-Agent 等自定义请求头。浏览器必须能访问视频源，HLS 播放列表、分片和密钥也必须满足浏览器的跨域及 HTTPS 要求；IP 绑定、防盗链、地址过期和编码不兼容仍可能导致失败。直链 URL（可能含签名）对客户端可见，源站会看到客户端 IP。

### Emby 客户端接入

支持 Emby VOD 客户端的核心登录、媒体库、检索、详情、季/集、图片、播放协商、直放/直流、HLS 转码、播放进度、收藏、已播放状态、会话和 WebSocket 心跳。协议同时挂载在根路径和 `/emby`；Token 可通过 `X-Emby-Token`、`X-Emby-Authorization`、`Authorization` 或 `api_key` 传递。媒体 ID、设备令牌、用户数据和索引持久化到 SQLite，重启后保持稳定。

1. 客户端服务器地址填写 `http://NAS地址:8788`，用户名和密码使用网页管理员创建的同一账号；不另设 Emby 密码。
2. Docker 默认发布 TCP 8788 和 UDP 7359。填写 `PUBLIC_BASE_URL=http://NAS局域网IP:8788` 后，同一局域网中支持发现的客户端可自动找到“片刻”；跨网段、反向代理或客户端不支持发现时手动填写地址。
3. 首次启动约 2 秒后开始后台扫描各来源目录，并按低并发提取详情、分季/分集及海报；已浏览或打开详情的内容也会立即入库。网页详情和 Emby 媒体库优先读取 SQLite，本地海报在服务重启后继续复用。全量扫描耗时和磁盘占用取决于来源数量及上游速度；管理员可通过 `POST /api/admin/catalog/sync` 触发同步。
4. Docker 镜像内置 FFmpeg/ffprobe。不兼容的 HEVC 等媒体可由客户端选择 HLS 转码；默认仅允许一个软件转码任务。硬件编码需将宿主机设备映射进容器，并设置匹配的 `TRANSCODE_VIDEO_CODEC`。
5. 客户端 API 行为存在版本差异。当前兼容面面向常见 Emby VOD 播放流程，不提供直播电视、音乐、插件管理、服务器升级、媒体文件写入或 Emby Connect 云服务。

主要协议入口：

| 接口 | 作用 |
| --- | --- |
| `GET /System/Info/Public`、`GET /System/Info`、`GET /System/Ping` | 服务器发现与状态 |
| `GET /Users/Public`、`POST /Users/AuthenticateByName`、`POST /Sessions/Logout` | 用户登录、设备 Token 和退出 |
| `GET /Users/:userId/Views`、`GET /Users/:userId/Items`、`GET /Items` | 媒体库、分页、筛选和搜索 |
| `GET /Shows/:id/Seasons`、`GET /Shows/:id/Episodes` | 剧集层级 |
| `GET /Items/:id/Images/:type/:index` | 海报与背景图 |
| `GET/POST /Items/:id/PlaybackInfo`、`GET /Videos/:id/stream.*`、`GET /Videos/:id/master.m3u8` | 播放协商、直放与 HLS 转码 |
| `POST /Sessions/Playing`、`POST /Sessions/Playing/Progress`、`POST /Sessions/Playing/Stopped` | 播放会话和进度同步 |
| `POST/DELETE /Users/:userId/FavoriteItems/:id`、`POST/DELETE /Users/:userId/PlayedItems/:id` | 收藏和已播放状态 |
| `GET /socket` | WebSocket 会话心跳与进度上报 |

### HTTP API

除 `GET /api/health`、`GET /api/auth/me`、`POST /api/auth/login` 外均需会话 Cookie；未登录返回 401，普通用户访问管理员接口或未授权来源返回 403。`user` 包含 `sourceIds: string[]`。所有 `/api/library` 请求还需 `X-Account-Id: <当前 user.id>`，缺失或不匹配返回 409。

| 接口 | 作用 |
| --- | --- |
| `GET /api/auth/me` | `{user}`，未登录时 `user: null` |
| `POST /api/auth/login` | `{username,password}`，成功设置会话 Cookie 并返回 `{user}` |
| `POST /api/auth/logout` | 撤销当前会话并清除 Cookie |
| `GET /api/admin/users` | 管理员读取账号列表，不包含密码或哈希 |
| `POST /api/admin/users` | 管理员提交 `{username,password,sourceIds?}` 创建普通用户；省略来源则选择当前全部，`[]` 表示无权限 |
| `POST /api/admin/users/:id/sources` | 管理员提交 `{sourceIds:string[]}`，返回 `{user}`；未知来源/无效数组返回 400，账号不存在返回 404，修改管理员权限返回 403 |
| `GET /api/library` | 当前账号有权访问来源的 `{favorites,recent}` |
| `GET /api/library/watch?key=...` | 当前账号的逐集进度 `{watch}`，不存在为 `null` |
| `POST /api/library/watch` | 保存当前账号的逐集进度；服务端生成复合键与保存时间 |
| `POST /api/library/favorite` | `{record}`，切换当前账号收藏，返回 `{favorite:boolean}` |
| `POST /api/library/remove` | `{kind:"history"\|"favorites",key}`，删除当前账号对应记录 |
| `POST /api/library/clear` | `{kind:"history"\|"favorites"}`，只清空当前账号有权访问来源的对应记录 |
| `GET /api/config` | 仅管理员；当前上游配置 `{backendUrl, persisted}` |
| `POST /api/config` | 仅管理员提交 `{backendUrl}`，持久化并立即应用；400 地址无效，403 无权限或跨站写入，409 正忙，500 保存失败 |
| `GET /api/sources` | 仅返回当前账号有权访问且上游已启用的来源、模块、筛选参数与组件加载错误 |
| `GET /api/admin/sources` | 仅管理员；先刷新上游组件列表（失败则忽略），返回全部已知来源 `{sources:[{id,title}]}`，用于账号授权 |
| `GET /api/sources/:id/browse?module=...&page=1` | 分类浏览，可附加模块参数 |
| `GET /api/sources/:id/search?q=...&page=1` | 当前源搜索 |
| `GET /api/sources/:id/detail?link=...` | 标准化详情、季和稳定分集 ID |
| `POST /api/sources/:id/playback` | `{link, episodeId, serverProxy?, refresh?}`；五分钟内复用最近的详情解析，`refresh: true` 强制重新解析；默认 `true` 返回本站中转线路，`false` 仅返回源站直链，无法解析直链时返回错误 |
| `GET /api/status` | 仅返回当前账号有权访问来源的状态；仅管理员返回当前上游地址，普通用户的 `backendUrl` 为空 |
| `POST /api/sources/:id/check` | 检查分类列表，不冒充播放验证 |
| `POST /api/sources/:id/playback-report` | 浏览器上报播放或编码错误 |
| `GET /api/media/:token` | 绑定账号与来源的短期媒体转发；借用其他账号凭证或已撤销来源权限返回 403 |
| `GET /api/posters/:id` | 稳定的同源海报地址；校验会话和来源权限，成功返回光栅图片；旧配置/未知标识返回 404，不可用图片返回 502 |

## 播放限制与排障

- **网页有声音但无画面：** 源可能是 HEVC/H.265，而浏览器或系统没有对应解码器。网页播放器仍使用原始媒体，不自动转码；可改用 Emby 客户端并选择 HLS 转码，或换用支持该编码的设备。转码能力取决于 NAS 的 CPU/GPU、FFmpeg 编码器和客户端协商结果。
- **保存失败：** 确认服务进程对 `DATA_DIR` 有写权限；Docker 使用提供的命名卷，不要把只读目录挂载到 `/app/data`。失败时输入草稿保留，当前配置不会改变。若连接中断，请刷新配置核实服务端是否已保存。
- **上游超时、入口不可用：** 先在来源状态页检查。Backend 的采集失败、源站验证、地区限制和下线会原样显示，不能由前端修复。黄豆组件的搜索仅覆盖其上游已浏览目录，这是源本身的能力限制。
- **解析较慢：** 某些客户端组件在详情阶段逐页解析所有集数，最多允许两分钟；可切换剧集或返回取消前端等待，服务端执行仍受总超时限制。
- **关闭中转后无法播放：** 若提示上游不支持直连或只提供中转地址，需上游公开真实源站 URL，或者手动开启“服务器代理中转”。若已取得直链但浏览器加载失败，检查客户端网络、跨域、防盗链、HTTPS 和编码；本站不会自动切回代理。
- **上游提供重复集数标识：** 组件返回了 ID 相同的多个剧集。播放地址也完全相同时，按同一集合并，只保留第一条，例如黄果单集影片会把相关推荐误识别为“第 1 集”。播放地址不同时无法判断该播哪一个，仍会报错，需要上游组件修正。
- **媒体地址过期：** 重新点击当前集、点击“重新获取地址”，或刷新详情。详情解析结果在服务端缓存五分钟，切集直接复用；重新点击当前集和“重新获取地址”会跳过缓存重新解析。只重载旧的播放线路无法延长上游地址有效期。
- **记录不见了：** 确认登录了同一账号、连接同一服务且数据卷仍存在；旧版匿名浏览器记录不会自动分配给账号。账号记录不依赖浏览器站点存储，清理 Cookie 后重新登录即可读取服务器记录。
- **海报缺失：** 海报始终通过本站接口读取，与视频代理开关无关。先查看 `/api/posters/:id` 状态：401 需登录，403 为来源权限不足，404 为旧配置/未知封面，502 为上游图片或候选不可用，503/504 为繁忙或超时。旧空记录会按内容标识恢复；源站已删除图片、只返回验证页或不支持的图片格式时不会伪装成功。
- **公开部署：** 使用 HTTPS，TLS 由反向代理终止时设置 `SESSION_COOKIE_SECURE=true`；使用独立强密码、登录限流和访问限制。反向代理请求超时应大于两分钟。账号系统不替代这些部署措施。
